# 原神音乐热度跨平台数据分析与可视化

> **信息可视化课程期末项目** | 2026
> **数据版本**：原神 7.1「往冥府的安魂歌」 · 数据基准 2026年10月 · 43 张官方专辑 / 122 位角色 / 9 大地区

---

## 一、项目概述

### 1.1 选题说明

本项目以《原神》游戏原声音乐（OST）为研究对象，围绕**跨平台数据采集、多源数据融合与空间可视化**展开。选题动机源于：单平台数据（如仅B站或仅网易云音乐）难以全面反映音乐作品的传播热度，因此需要建立跨平台数据交叉验证体系。

### 1.2 数据来源

所有数据均可公开检索验证，承诺零虚构、零插值：

| 平台 | 数据项 | 采集方式 |
|------|--------|----------|
| 网易云音乐 | 专辑收藏量、评论数 | API 获取 |
| QQ音乐 | 歌曲播放量 | 页面爬取 |
| 哔哩哔哩 | PV / 官方视频播放量 | 搜索匹配 |

### 1.3 技术方案

| 类别 | 技术 | 选型理由 |
|------|------|----------|
| 前端 | 原生 HTML5 / CSS3 / ES6+ | 无框架依赖，纯静态部署 |
| 地图 | Leaflet.js | 开源、轻量，支持自定义瓦片与标记 |
| 字体 | Noto Sans SC / Serif SC | 中文排版友好 |
| 资源 | 本地静态资源 | 头像、立绘、图标均为本地加载，避免 CDN 不可用 |

## 二、从数据到洞察

### 2.1 数据采集与清洗

为构建可靠的数据基础，项目实施了严格的三级处理流程：

- **多源采集**：覆盖网易云音乐（收藏量+评论数）、QQ音乐（播放量）、B站（PV播放量）三个平台
- **标准化处理**：统一数值单位为千（k），消除跨平台数量级差异
- **去重与交叉验证**：以专辑ID、曲目全称为主键进行三平台匹配，缺失项标记为"数据不全"
- **异常值过滤**：剔除播放量为0或明显异常的样本

### 2.2 分析方法

面对多源、多维度、数量级差异悬殊的数据，项目采用了以下分析策略：

**分类分析**：按9大地区（蒙德、璃月、稻妻等）和7种元素（火/水/冰/雷/风/岩/草）进行分组对比，揭示不同维度下的热度分布规律。

**关联分析**：计算网易云收藏量与B站播放量的相关性，探究"收藏→传播"的转化链路，以及剧情场景热度与角色主题曲热度之间的关联度。

**综合热度评分**：针对三平台数据口径不统一的问题，设计了加权融合公式：

```javascript
// 综合热度 = 网易云收藏(40%) + QQ播放(30%) + B站播放(30%)
score = (neteaseFav / 2) * 0.4 + (qqPlays / 5) * 0.3 + (biliPlays / 10) * 0.3
```

在此基础上采用对数归一化，将跨度极大的播放量映射到 0–100 的评分区间，使不同量级的数据具备可比性。

### 2.3 叙事结构

作品整体采用"总 → 分 → 深"三层递进的组织方式：

1. **总览**：地图首页以热力图展示全大陆热度分布，提供宏观视角
2. **分类**：按地区、角色、专辑等维度进行下钻，逐层细化
3. **深度**：专辑页展示曲目级的三平台数据对比，完成交叉验证

## 三、视觉表达

### 3.1 图表选型

针对不同数据特征，选择最合适的可视化形式：

| 数据类型 | 可视化形式 | 设计理由 |
|---------|-----------|---------|
| 地理分布 | 交互式地图（Leaflet） | 贴合游戏世界观，直观展示空间分布 |
| 多维对比 | 雷达图 | 对比不同地区在收藏/评论/播放维度的表现 |
| 排名分布 | 横向条形图 | 清晰展示 TOP 曲目/专辑的排名与差距 |
| 热度强度 | 热力图图层 | 利用色彩密度表达热度，识别热点区域 |
| 数据关联 | 散点图 | 展示收藏量与播放量的相关性 |

### 3.2 视觉编码

- **元素色彩映射**（与游戏设定一致）：火-红、水-蓝、冰-青、雷-紫、风-绿、岩-黄、草-翠
- **热度等级配色**：现象级(红)>75、高热度(金)>50、中等(紫)>25、常规(灰)<25
- **信息层级**：标题(20px) > 副标题(16px) > 正文(13px) > 数据(11px)，三级字号体系

### 3.3 布局

- 响应式网格布局，自适应不同屏幕尺寸
- 侧边栏 + 主内容区经典布局，地图为主、数据为辅
- 卡片间距统一（12px/16px），视觉层次分明

## 四、交互体验

作品提供了丰富的交互手段，支持用户自主探索数据：

| 交互类型 | 功能实现 |
|----------|----------|
| 筛选过滤 | 按地区（9个标签页）、按元素（7种组合）、按稀有度（4星/5星）、实时搜索（角色名模糊匹配） |
| 缩放平移 | 地图滚轮缩放 + 拖拽平移，一键全图/全屏 |
| 点击下钻 | 地区标记 → 地区详情；角色标记 → 角色音乐数据；专辑卡片 → 曲目列表 |
| 动态变化 | 热力图图层动态切换，Tab 切换时数据平滑过渡 |
| 状态管理 | URL hash 管理视图状态，支持浏览器前进/后退 |
| 反馈机制 | 悬停卡片上浮动画 + 阴影增强 |
| 容错处理 | 图片加载失败自动隐藏（onerror），避免布局混乱 |

## 五、技术实现

### 5.1 架构设计

```
展示层 (HTML) → 样式层 (CSS) → 逻辑层 (JS) → 数据层 (data.js)
```

项目采用分层架构，各页面独立 JS 文件，核心数据统一在 `data.js` 中管理。纯静态部署，无需后端服务，可运行于任何静态托管平台。

### 5.2 性能优化

- 图片懒加载，优化首屏加载时间
- 事件委托减少监听器数量
- 浮点数精度修复，`fmt()` 统一处理千/万单位格式化

### 5.3 自主开发

全部代码自主编写，从数据采集、清洗、存储到可视化渲染均未使用第三方模板或 UI 框架。地图部分基于 Leaflet 定制了提瓦特大陆的瓦片与标记系统。

## 六、特色与创新

- **选题前瞻**：将信息可视化技术应用于游戏音乐跨平台分析，填补了该细分领域的研究空白
- **多源融合**：打破单平台数据局限，建立三平台交叉验证方法，提升分析结论的可靠性
- **空间叙事**：将抽象的音乐热度数据映射到游戏世界观的地理空间，实现数据与内容的深度融合
- **研究价值**：为游戏音乐传播研究提供可复用的数据采集与分析范式
