# 原神音乐热度跨平台数据分析与可视化

> 信息可视化课程期末项目 · 2026
> 数据版本：原神 7.1「往冥府的安魂歌」 · 数据快照：2026 年 10 月
> 样本规模：122 位可玩角色 / 43 张官方专辑 / 9 大地区 / 约 1,700 首带网易云 ID 的曲目逐首核对

---

## 一、摘要

本项目以《原神》官方原声音乐（OST）与角色 PV 为研究对象，构建了一个**可核实、可复现、零虚构**的跨平台音乐热度数据集，并在其之上完成统计分析型可视化。项目的核心不是"展示一堆漂亮图表"，而是回答四个可检验的数据分析问题：不同平台的互动指标之间是否存在稳定的数量关系？热度在地区、元素、武器、星级等结构维度上是否存在系统性差异？曲目级评论分布呈现何种形态、极端值占比多少？以及，跨平台的传播量级可以被解读到什么程度、又不能被解读到什么程度。

为避免常见的"看起来专业、实际上不成立"的结论，本项目在全站统一了统计口径：所有分组比较以**中位数**为主、以**四分位距（IQR）**衡量离散程度、以**百分位**定位个体、以 **Pearson r 与 r²** 量化关联强度、以 **Tukey 规则（Q3+1.5×IQR）**识别异常值，并在页面中显式标注样本量 n 与指标口径。所有无法从平台公开数据核实到的字段（例如 QQ 音乐单曲播放量）一律留空，不做估算、不做插值、不做模型填充。

## 二、研究问题

| 编号 | 研究问题 | 主要方法 | 对应页面 |
|------|----------|----------|----------|
| RQ1 | 角色 PV 播放量与音乐平台收藏量的关联强度如何？是否存在系统性"高曝光低转化"的错位角色？ | Pearson r、r²、中位数四象限分类 | 数据洞察 / 角色音乐 |
| RQ2 | 热度在地区、元素、武器类型、星级等结构维度上是否存在差异？差异是结构效应还是样本噪声？ | 分组中位数、分组 n、占比结构 | 地区探索 / 数据洞察 |

| RQ4 | 从 B 站曝光到音乐平台互动的量级衰减如何？该指标可以被解读为什么、不能被解读为什么？ | 量级占比（非同源归一）、口径说明 | 数据洞察 |

## 三、数据来源与指标口径

### 3.1 数据来源

| 平台 | 数据项 | 采集方式 | 可核实性 |
|------|--------|----------|----------|
| 哔哩哔哩 | 角色 PV 累计播放量 | 官方视频页公开计数 | 逐条核对 |
| 哔哩哔哩 | 曲目相关视频播放量（「原神 + 曲名」最相关视频） | 搜索匹配后取公开计数 | 逐首核对 |
| 网易云音乐 | 角色主题曲收藏量、PV 评论数 | 公开歌曲页计数 | 逐条核对 |
| 网易云音乐 | 单曲评论总数 | 公开歌曲页计数 | 逐首核对 |
| QQ 音乐 | 角色主题曲收藏量 | 公开歌曲页计数 | 逐条核对 |
| QQ 音乐 | 单曲播放量 | — | **无公开数据，字段留空** |

### 3.2 两级指标体系（关键约束）

项目的指标分为两层，**两层不同源、不同样本，不可相加，也不可换算**：

- **角色级**（样本 = 122 位可玩角色）
  - B 站角色 PV 累计播放量（单位：万）
  - 网易云 / QQ 音乐主题曲收藏量（单位：千）
  - PV 评论数（单位：千）
- **曲目级**（样本 = 可核实曲目，去重后逐首统计）
  - 网易云单曲评论总数（绝对值，单位：条）
  - B 站相关视频播放量（绝对值，单位：次）
  - 无平台公开来源的曲目，其相关字段直接置空，不参与任何统计

### 3.3 曲目综合热度分

曲目级热度分采用**对数归一 + 权重归一**，避免直接相加量级差异悬殊的两个指标：

```javascript
// 评论项权重 0.4，播放项权重 0.6；缺失一项时按可用权重归一，两项皆缺失则记 0
heat = log10(1 + neteaseCmt) / 5 * 0.4
     + log10(1 + biliPlay)   / 7 * 0.6
```

对数变换用于压缩长尾、抑制少数极高值对排序的支配；权重归一用于保证"只有评论"或"只有播放"的曲目不会被无理由地系统性压低。热度分仅用于**同一指标口径下的排序**，不构成跨平台的统一"真实热度"。

## 四、数据采集与清洗

1. **全量逐首核对**：对约 1,700 首带网易云 ID 的曲目逐首访问公开页面，获取评论数与 B 站相关视频播放量。
2. **按来源留空**：无法从平台公开页面核实到的字段一律写为 `null`，并在前端以"暂无真实平台数据"显式呈现，而不是填 0 或估算值。
3. **去重规则**：曲目以中文主曲名（英文后缀剔除）为键去重；专辑曲目、剧情曲目、地区曲目三处来源合并后统一去重，避免同一首曲目被重复计入样本（跨来源同名曲目此前确实存在，已通过三级匹配修正）。
4. **单位统一**：角色级保留平台原始单位（万 / 千），曲目级统一为绝对计数；所有跨组比较在同一层内完成，不跨层换算。
5. **样本偏差声明**：可核实曲目是全部官方曲目的**子集**，覆盖率在音乐专辑页实时计算并展示，统计结论仅对该子集成立。

## 五、统计方法

全站统计工具集中在 `js/data.js`，所有页面共用同一实现，避免各页口径漂移：

| 方法 | 实现 | 用途 |
|------|------|------|
| 分位数 / 中位数 | `statQuantile` / `statMedian` | 右偏分布下的稳健中心度量，替代均值 |
| Q1 / Q3 / IQR | `statQ1` / `statQ3` / `statIQR` | 离散程度与箱线图箱体 |
| 变异系数 CV | `statCV` | 跨指标、跨量级可比的波动度量 |
| Pearson 相关 | `statPearson` | RQ1 关联强度，配合 r² 解释可解释方差比例 |
| 相关强度分级 | `statCorrLabel` | 按 Cohen 惯例（0.2 / 0.4 / 0.7）标注极弱 / 弱 / 中等 / 强 |
| 百分位排名 | `statPercentileRank` | 个体在全体中的相对位置（P0–P100） |
| 可核实曲目普查 | `getVerifiedTrackCensus` | 合并三处曲目来源并去重，构成曲目级分析样本 |

方法使用原则：

- **中位数优先**：热度类指标普遍右偏，均值会被头部曲目显著抬高，因此分组比较以中位数为主，均值仅作为对照并在页面注明"受极值抬高"。
- **必须给出 n**：任何分组结论都同时展示该组样本量，n 过小的组不作为结论依据。
- **相关 ≠ 因果**：r 只描述同向变化程度，不解释机制；页面同时展示 r² 以说明"仅能解释多少比例的方差"。
- **非同源不可换算**：B 站曝光与网易云互动来自不同用户池，任何"转化率"表述都被明确禁止，改为"量级占比"。

## 六、分析结果

以下结论均由页面在运行时基于当前数据实时计算，文中不固化具体数值，以保证口径变更后结论不会与图表脱节。

### 6.1 RQ1 平台联动

角色 PV 播放量与网易云收藏量之间呈现正相关，具体强度以数据洞察页实时计算的 r 与 r² 为准。以两项指标的**中位数**为界划分四象限后可以看到：多数角色落在"高 PV 高收藏"与"低 PV 低收藏"两个同向象限，但同时存在"高 PV 低收藏"的曝光错位角色——这类角色说明 PV 曝光并不必然带来音乐平台沉淀，二者虽同向但并不等价。散点气泡以 PV 评论数编码，用于同时观察"播放—收藏—讨论"三层强度。

### 6.2 RQ2 结构差异

- **地区**：以角色 PV 为单位观察，各地区人均 PV 存在数倍差距；由于地区内角色数量差异较大，结论以各地区中位数与 n 为准，人均值仅作辅助。
- **元素 / 武器**：分组中位数与占比结构同时展示，用于区分"该组角色本来就多"的结构效应与"该组角色确实更热"的强度效应。
- **星级**：5 星与 4 星角色的 PV 中位数差异被单独量化，避免用整体均值掩盖分层差异。

### 6.3 RQ3 分布形态

曲目评论数呈典型**右偏长尾**：中位数显著低于均值，Q3 与 Q1 之间集中了大部分曲目，而按 Tukey 规则（Q3+1.5×IQR）越界的少数曲目贡献了绝大部分互动量。变异系数 CV 进一步量化了这种离散程度。因此所有"平均热度"类表述都被替换为"典型曲目（中位数）"与"头部曲目"两档描述。

### 6.4 RQ4 传播量级

以 B 站 PV 曝光为基准观察音乐平台互动的量级占比，可以得到"曝光 → 收藏 → 评论"逐级衰减的量级关系。该结果只描述**不同平台上群体行为的相对规模**，不能解读为用户级转化率，也不能用于推断单个用户的路径。

## 七、可视化与交互设计

| 数据类型 | 可视化形式 | 统计编码说明 |
|---------|-----------|--------------|
| 地理分布 | Leaflet 交互地图 + 热度图层 | 地区面板同时展示角色级与曲目级指标，标签明确标注平台 |
| 多维对比 | 雷达图 | 五维指标经 log1p 后 min-max 归一至 0.08–1，标注"相对强弱" |
| 分布形态 | 箱线图（12 箱） | 箱体 = Q1–Q3，中线 = 中位数，须 = Tukey 界，离群点单独标记 |
| 关联关系 | 散点图 | 中位数虚线四象限 + 象限人数 + r / r² 标注 |
| 排名与差异 | 横向条形图 / 分组条形图 | 同时展示人均（均值）与中位 PV |
| 时间与版本 | 版本时间轴 | 仅使用实测评论与播放，按百分位标注头部 / 高位 / 中位 / 尾部 |

交互采用"总览 → 分组 → 个体"三级下钻：地图选地区 → 地区详情 → 角色详情；专辑卡片 → 曲目列表 → 平台跳转。所有图片均带 `onerror` 兜底，CDN 不可用时回退本地素材。

## 八、技术实现

```
展示层 (HTML) → 样式层 (CSS) → 逻辑层 (各页 JS) → 数据层 (data.js + 统计工具)
```

- 纯静态：HTML5 / CSS3 / 原生 ES6+，无框架、无第三方图表库，图表均为手写 SVG / Canvas。
- 地图：Leaflet + 本地瓦片，坐标手工校准，视图约束在内容范围内。
- 数据层：`data.js` 统一存放角色、专辑、曲目、真实指标与统计函数，各页只消费不重复定义。
- 缓存治理：脚本引用统一带版本号参数，避免浏览器读到旧逻辑。

## 九、讨论与局限

1. **样本非总体**：可核实曲目是官方曲目的子集，覆盖率见音乐专辑页；未覆盖部分不参与推断，因此曲目级结论存在样本偏差。
2. **单次快照**：所有计数为 2026 年 10 月的单次抓取，不具备时间序列，无法做趋势判断或因果识别。
3. **指标不可换算**：B 站播放、网易云评论、平台收藏的用户池不重合，三者只能各自比较，任何比值都不具备"转化率"含义。
4. **平台口径差异**：B 站"相关视频播放"是搜索结果中单条最相关视频的播放量，反映的是该曲目在视频生态中的曝光上限，而非全站总播放。
5. **缺失值处理**：缺失一律留空而非填 0，这在统计上更保守，但也意味着部分分组的中位数仅基于可用子样本，页面已标注各组 n。
6. **行业外部因素未建模**：版本节奏、角色人气、活动联动等未纳入模型，因此结构差异只能描述，不能归因。

## 十、结论

1. 跨平台热度存在稳定同向关系，但同向不等于等价：曝光与音乐沉淀之间存在可观测的错位角色，这部分错位比"总体正相关"更有分析价值。
2. 曲目级互动呈强右偏长尾，少数头部曲目主导总量；因此以中位数描述"典型水平"、以百分位描述"个体位置"、以 Tukey 界识别"极端样本"，是这套数据唯一站得住的分析框架。
3. 结构维度（地区、元素、武器、星级）的差异必须与样本量一起读，否则容易把"人多"误读为"更热"。
4. 跨平台量级可以比较规模，不能推断转化；这是本项目在方法上刻意守住的一条边界。
